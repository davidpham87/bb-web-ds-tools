Themes, Dreams, and R Graphics: A Visual Awakening

By The "We Only Code in Dark Mode" Team

Greetings, fellow data wranglers and pixel pushers.

We come to you today with an announcement that will shake the very foundations of your browser tab (assuming you have less than 50 open, which we know you don't). We have made changes. Are they groundbreaking? Debatable. Are they visible? Yes, very.

Zenburn: Because Bright White is an Act of Aggression

First up, let's talk about aesthetics.

For too long, software tools have defaulted to blinding white backgrounds, presumably to simulate the experience of staring directly into the sun while trying to debug a race condition. We say: No more.

We have fully embraced the Zenburn theme. Not just because it sounds like a yoga studio for burned-out developers, but because it’s soothing. It’s calm. It’s a mix of #3f3f3f and #dcdccc that says, "It’s okay, that null pointer exception can’t hurt you here."

Every button, every panel, every scrollbar has been meticulously styled to ensure that your eyes don’t bleed after a 4-hour coding session. We’ve aligned the pixels. We’ve harmonized the contrasts. We probably spent more time on the color of the "Delete" button than the actual deletion logic. Priorities.

R Graphics in Portal: Pictures > Text

Now, the main event.

We have an R runtime (WebR) in the browser. It’s amazing. It’s magical. But until recently, if you plotted something, you had to use your imagination. You’d run plot(mtcars), and the console would stare back at you, blank and judging.

Well, we fixed it.

Thanks to our obsession with Portal, when you generate a plot in R, we now intercept it, wrap it in a warm embrace, and display it directly in the Portal viewer.

You run the code. You get the chart. Instant gratification.

Why read a summary statistic when you can look at a scatter plot and pretend you see a correlation? Why look at a table of numbers when you can generate a histogram that proves your data is completely skewed?

We’re giving you the power to create beautiful, informative graphics that you can then screenshot and put in a slide deck that nobody will read. And really, isn’t that what Data Science is all about?

Conclusion

So, enjoy the new theme. Enjoy the R graphics. And please, for the love of all that is holy, close some tabs.

CLI Tools Guide: Or How I Learned to Stop Worrying and Love the Terminal

CLI Tools Guide: Or How I Learned to Stop Worrying and Love the Terminal

2025-12-07

Welcome, brave data explorer. You've likely found yourself here because the beautiful, pixel-perfect web interface of bb-web-ds-tools was just too "easy" for you. You crave the raw power of the command line. You want to feel the bits flowing through your fingertips. Or maybe you just need to script something and don't want to use a headless browser. Whatever your reason, we support you. Sort of.

In this guide, we'll walk through the CLI tools available in this repository. They are, essentially, wrappers around the same logic that powers the web app, but with less clicking and more typing.

Prerequisites

You'll need babashka installed. If you don't have it, go get it. We'll wait.

The Tools

We have three main tools for your enjoyment: data, sql, and schema.

You can access them all via the dstools entry point:

bb -m dstools <command> <subcommand> [opts]

1. Datasets: The Data Plumber (data)

The data tool is your Swiss Army knife for converting data formats. Because sometimes you have JSON, but you really, really want EDN. Or maybe YAML, because you're feeling adventurous.

Structure Guessing: By default, the tool guesses the structure of your data (e.g., row-maps vs columnar). You can explicitly control this with --input-struct and --output-struct. See docs/CLI_DATA_STRUCTURES.md for details.

Usage:

bb -m dstools data convert [opts]

Options:

  • -f, --format <fmt>: Input format (csv, json, edn, yaml). Optional if it can be inferred from the filename extension.
  • -t, --to <fmt>: Output format (csv, json, edn, yaml). Default: json.
  • -i, --file <file>: Input file. Reads from stdin if omitted.
  • -o, --out <file>: Output file. Writes to stdout if omitted. Inferred from input filename if possible (e.g., input.json -> input.edn).
  • -S, --input-struct <struct>: Input data structure (row-maps, columnar, rows).
  • -s, --output-struct <struct>: Output data structure (row-maps, columnar, rows).

Example: Converting Cars

Let's take a classic dataset, cars.json (from the Vega datasets collection), and convert it to EDN. Why? Because keywords are better than strings. Everyone knows that.

First, imagine you have cars.json:

[
  {
    "Name": "chevrolet chevelle malibu",
    "Miles_per_Gallon": 18,
    "Cylinders": 8,
    "Displacement": 307,
    "Horsepower": 130,
    "Weight_in_lbs": 3504,
    "Acceleration": 12,
    "Year": "1970-01-01",
    "Origin": "USA"
  },
  {
    "Name": "buick skylark 320",
    "Miles_per_Gallon": 15,
    "Cylinders": 8,
    "Displacement": 350,
    "Horsepower": 165,
    "Weight_in_lbs": 3693,
    "Acceleration": 11.5,
    "Year": "1970-01-01",
    "Origin": "USA"
  }
]

Now, let's convert it to EDN. Notice we don't even need to tell it the input format, because we named our file properly:

bb -m dstools data convert -t edn -i cars.json

This will create cars.edn automatically. Your cars.edn will look something like this (but prettier, because EDN is beautiful):

And if you want to join the YAML revolution:

bb -m dstools data convert -t yaml -i cars.edn

Boom. cars.yaml.

2. HoneySQL: The Query Whisperer (sql)

You write Clojure data structures. You get SQL strings. It's magic, but with more parentheses.

Usage:

bb -m dstools sql convert [opts]

Options:

  • -i, --file <file>: Input file containing a HoneySQL map. Stdin if omitted.
  • -o, --out <file>: Output file. Inferred from input filename (e.g., query.edn -> query.sql).

Example:

Input query.edn:

{:select [:*]
 :from [:cars]
 :where [:= :Origin "USA"]}

Command:

bb -m dstools sql convert -i query.edn

Output (to query.sql):

SELECT * FROM cars WHERE Origin = 'USA'

3. Malli: The Schema Enforcer (schema)

Infer schemas, generate data, and validate your life choices (or at least your data).

Commands:

  • infer: Guess the schema from data.
  • generate: Create random data from a schema.
  • validate: Check if data matches a schema.

Example: Inferring Schema from Cars

Remember that cars.edn file? Let's see what Malli thinks of it.

bb -m dstools schema infer -i cars.edn

Output (something like):

[:vector
 [:map
  [:Name string?]
  [:Miles_per_Gallon int?]
  [:Cylinders int?]
  [:Displacement int?]
  [:Horsepower int?]
  [:Weight_in_lbs int?]
  [:Acceleration double?]
  [:Year string?]
  [:Origin string?]]]

And there you have it. The CLI tools. Use them wisely, or at least use them to avoid opening a browser.

CLI Tools for Data Science

CLI Tools for Data Science: Because clicking is hard

Sometimes you just want to pipe data around in your terminal like a plumber from the 80s. We get it. That's why we've exposed the core functionality of bb-web-ds-tools as a CLI library compatible with Babashka.

Setup

First, make sure you have Babashka installed. Then, you can run these tools directly from the source or by adding this repo as a dependency.

# Clone the repo
git clone https://github.com/my-org/bb-web-ds-tools.git
cd bb-web-ds-tools

# Add deps (if not using bb directly with classpath)
# You might need to set up your bb.edn to include paths "src"

You can use the -x flag in Babashka to execute a function directly from the CLI.

Datasets

Convert between CSV, JSON, and EDN without opening Excel.

Example: CSV to JSON

# Convert a CSV file to JSON
bb -cp src -x bb-web-ds-tools.cli.datasets/convert --format csv --to json --file data.csv

# Or pipe it
cat data.csv | bb -cp src -x bb-web-ds-tools.cli.datasets/convert --format csv --to json

Example: EDN to CSV

echo '[{:a 1 :b 2} {:a 3 :b 4}]' | bb -cp src -x bb-web-ds-tools.cli.datasets/convert --format edn --to csv

Malli

Validate data and infer schemas from the comfort of your shell.

Infer Schema

Got a huge JSON blob and don't know what's in it?

cat large.json | bb -cp src -x bb-web-ds-tools.cli.malli/infer

Generate Data

Need mock data for your API?

echo '[:map [:name string?] [:age int?]]' | bb -cp src -x bb-web-ds-tools.cli.malli/generate --samples 5 --format json

Validate Data

bb -cp src -x bb-web-ds-tools.cli.malli/validate --schema schema.edn --file data.json

HoneySQL

Write data structures, get SQL.

echo '{:select [:*] :from [:users] :where [:= :active true]}' | bb -cp src -x bb-web-ds-tools.cli.honeysql/convert

Output:

SELECT * FROM users WHERE active = TRUE

Why?

Because sometimes the browser is too far away (Alt-Tab is hard). Enjoy!
